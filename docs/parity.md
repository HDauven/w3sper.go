## Independent fixtures

`walletcore/parity_test.go` reads `testdata/js-oracle.json`, generated by the actual
pinned JS SDK, not by this port. Seven deterministic signed transaction fixtures
are checked through both low-level wallet-core and high-level builders. Randomized
Phoenix proofs/signatures are **not compared byte-for-byte**: note semantics,
acceptance, nullifiers, account/private deltas and actual execution are checked.

The coordinator also independently compared all 12 assigned wallets across JS,
Go and Python: identity, account/private balances, stake state/owners, unspent note
and nullifier bytes, bookmarks and note root matched. That snapshot is separate
from the SDK's own tests and does not imply the ports share ownership authority.

History enrichment is associated by GraphQL alias rather than response-object
order. This intentionally avoids the pinned JS history bug that can attach another
transaction's fees, method and block metadata to a hash when aliases arrive out of
order. The Go results were independently checked against node receipts by hash.

## Local live run

Node: fresh lab state, pinned Rusk 1.7.1, Phoenix genesis, archive + real prover,
chain ID 42, `http://127.0.0.1:18280`. Go submits only profiles 10–13. Seed is the
public synthetic byte sequence 0..63; no production keys are used.

`cmd/live-parity -group all -submit` executed 22 transactions:

- Public/private memos, shield and unshield (4).
- Public/private contract deposits and decoded events (2).
- Public/private Bob deployment initialization and persistent resets (4).
- Host-backed committed target deployment and persistent committed `run` (2).
- Public/private stake, top-up, partial/full unstake and reward withdrawal (10).

Every successful transaction captures before/after state for all four profiles,
checks exact account/Phoenix/nonce deltas including actual fees, compares the
execution-event fee with mined gas, and verifies consumed nullifiers. Stake
ownership and remaining amounts/rewards are checked independently; new stakes
are fully closed. Finalized public history is checked against transaction values
and fees. Corrupt public/private transactions fail preverification; wrong-owner
builds fail before submission. Block accepted/statechange notifications, transport
health, contract metadata/feeder reads and pre-aborted queries are also checked.

Local evidence (not required by offline tests):
`/home/hein_/projects/w3sper-parity-lab.CY060e/checks/go-live-final.{json,log}`.
The original trial used a legacy A ABI target for a committed call and correctly
reported execution `err="Unknown"`; those failed reports are retained. The
coordinator supplied a B ABI fixture and verified it independently through JS.
The corrected committed call succeeds and changes all 32 state bytes from 7 to 9.
This was a test-target correction, not a cryptographic or node-policy bypass.

## Remaining limits / non-claims

No known required **feature-family** omission remains in the exercised matrix.
That is not proof of every observable JS behavior or every failure interleaving.

1. **Synchronous providers:** a Go callback that ignores its context cannot be
   interrupted without abandoning its running work. SDK-owned network I/O and
   admission waits are cancelable; legacy/context-ignoring seed, treasury, source,
   custom transport/marshaler/progress callbacks and local file reads have a
   synchronous ceiling. JS can race asynchronous provider promises and return
   earlier. This timing difference is not claimed equivalent.
2. **Native crypto:** running wallet-core WASM is synchronous and non-preemptive,
   matching the JS documented ceiling. Stale authority results are rejected;
   arbitrary data-driver WASM is interruptible, retiring its instance. Secret
   erasure and revocation of already-issued signatures are not guaranteed.
3. **Operation scope:** no durable wallet DB, nonce/note reservation, automatic
   finality, automatic reconnect/replay or reorg reconciliation is added. Raw
   event payloads are owned bytes; Go callers decode explicitly. Account history
   is one pull stream per requested account, rather than a JS array of streams.
4. **Network/ABI scope:** committed dispatch needs a host-backed B ABI target and
   appropriate network activation. Contract-owned stakes require contract
   authority, not a fabricated wallet signer. Arbitrary network versions and
   production deployment policy are not validated by the local acceptance run.
5. **Validation choices:** malformed inputs may fail earlier than JS. Empty memos
   omit transaction data like the pinned driver. No implicit float64 narrowing or
   silent invalid-gas defaulting is emulated. Legacy seed/index low-level calls
   remain adapters for source compatibility; new wallet workflows require explicit
   signer capabilities and caller contexts.
6. **Testing scope:** the tests exercise selected cancellation/resource races,
   malformed modules/archives and live rejections, not an exhaustive fuzz audit.
   Data-driver results use the same 64 KiB output capacity as the pinned loader.
   Real artifacts are pinned by digest; future protocol releases need revalidation.
